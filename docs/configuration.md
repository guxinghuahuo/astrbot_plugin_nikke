## RSSHub 地址与国际服直连（v1.2.0）

- **RSSHub 地址**（`base.rsshub_base_url`）：仅填写一个地址，bilibili 动态和配图回退使用它。
- **国际服直连官方接口**（`base.international_direct`）：默认开启，无需部署 RSSHub；关闭后，国际服也使用上面的 RSSHub 地址，需要部署附带的国际服路由。
- **国际服图片代理**：大陆地区通常无法直接访问国际服图片。如需获取动态图片，建议配置 HTTP 代理，例如 `http://192.168.0.2:7890`。

国际服四种语言保持相同的帖子 ID、正文解析、时间、图片顺序和原链接。切换获取方式保留来源标识、基线、去重、存档和待投递进度；翻译的繁中参考自动使用所选方式。直连不依赖 RSSHub 的 300 秒缓存，当前页可能比已有 RSS 缓存更新。API 仅请求近期一页，不能保证补齐长时间停机期间的历史。

国际服官方正文接口直连，不使用图片代理；图片下载仍使用原有代理设置。bilibili 更换实际地址仍视为新来源，会重新建立基线，请先处理待投递任务并备份数据。

只读自检：`python scripts/check_international.py --source direct --skip-images`；兼容模式使用 `--source rsshub --rsshub http://自己的服务:1200`。去掉 `--skip-images` 可检查原图，脚本不发送群消息。


## 配置与首次验证

配置页按以下顺序分组显示：

1. **基础配置**：自动推送、RSSHub 地址、检查间隔、随机扰动、图片及 QQ 平台选择。
2. **订阅及目标群**：订阅来源、语言及目标群列表。
3. **国际服非中文动态翻译**：翻译开关、模型、繁中参考等待上限、关闭思考开关及自定义参数。
4. **国际服配图回退**：bilibili 配图匹配、重试间隔及最长等待时间。
5. **AI 内容筛选**：AI/Jev 开关、模型、Token、置信度和超时。
6. **聊天查询工具**：工具开关、单次查询天数和返回字符限制。
7. **提示词模板**：大模型和 Jev 的可编辑提示词与分类条件。
8. **活动倒计时提醒**：国际服活动类别、独立目标群、提醒档位和夜间汇总。

已有平铺配置会在升级时自动迁移，保留 Token、开关、模型等设置，无需重新填写。配置文件使用 `base`、`ai_filter`、`chat_tools` 三个对象保存对应区块，`subscriptions` 仍保留为列表。插件兼容旧格式；新建配置和未填写阈值时，Jev 默认使用 0.8，已有自定义阈值不会因迁移自动重置。

在 WebUI 的「NIKKE 资讯助手」配置中填写以下信息，点击保存即可自动重载生效：

| 项目 | 配置示例 |
| --- | --- |
| RSSHub 地址 | `http://rsshub:1200` |
| 自动推送 | 初始关闭，验证完成后开启 |
| 检查间隔 | 300 秒 |
| 随机扰动 | ±60 秒，即正常轮询 240～360 秒 |
| AI 内容筛选 | 默认关闭，按需选择模型后开启 |
| 订阅名称 | `NIKKE官方` |
| bilibili UID | `3546734206650905` |
| 目标 QQ 群号 | `123456789` |

目标群列表每项只填写一个 QQ 群号，无需获取 `/sid`。插件自动使用唯一的 OneBot QQ 平台；若接入多个 OneBot 账号，请在「QQ 平台 ID（多账号时填写）」中指定发送账号的平台 ID（见 AstrBot 消息平台页面），避免选错账号。旧版完整会话标识仍兼容。改填群号并使用原发送账号时，已有基线、去重记录和待发送队列都会保留；更换账号会作为新目标建立基线。配置样例在 [../examples/nas-config.json](../examples/nas-config.json)；对应持久配置文件是 `data/config/astrbot_plugin_nikke_config.json`。已有配置应在 WebUI 修改，避免被运行中的配置覆盖。

可用指令（状态、检查、订阅、退订仅限 AstrBot 管理员，其余所有人可用）：

```text
/nikke
/nikke 帮助
/nikke 状态
/nikke 订阅
/nikke 订阅 NIKKE国际服
/nikke 退订 NIKKE国际服
/nikke 活动
/nikke 角色 小红帽
/nikke 技能 拉毗：小红帽 7
/nikke 检查 NIKKE官方
/nikke 最新 NIKKE官方
```

「检查」读取 RSS 并返回条数、最新时间和原链接；开启 AI 时还返回最新动态的分类和理由，不建立基线、不转发动态。「最新」会把通过筛选的最新一条图文发到当前群，仅允许在该订阅配置的目标群中执行；被过滤时只返回说明。两者共用 30 秒检查间隔；自动推送关闭时仍可手动检查和预览。

「订阅」「退订」只允许 AstrBot 配置的管理员使用，QQ 群主或群管理员身份本身不授予此权限。
先在 WebUI 配置并启用来源；不带名称时仅列出可用来源和完整命令，不执行修改。
指定精确名称后，订阅将当前 OneBot QQ 群或私聊账号加入该来源的目标列表；退订将当前会话移出。
不接受其他群号或账号作为参数，不自动纠正名称后执行修改。多账号接入时以当前消息所属的 OneBot 平台为准。
同一群或私聊账号只支持一种国际服语言，语言冲突时拒绝修改。
修改保存到 `data/config/astrbot_plugin_nikke_config.json`，立即生效并在重启后保留，也会显示在 WebUI 的目标列表中。
聊天添加的目标以完整会话标识保存，私聊形式例如 `qq:FriendMessage:123456789`，请保留该形式。
已有订阅重复执行不会重建基线；退订清除当前会话对应的待投递和补图任务，其他会话保持原样。
再次订阅会建立新基线，不补发退订期间的旧动态。自动推送总开关仍由 WebUI 控制，关闭时会提示已保存但不会自动推送。
这些指令仅管理动态订阅，不改变「活动倒计时提醒」独立配置的目标。

手动检查和预览也会将获取的动态写入资料存档，但不会改变投递队列或建立基线。

国际服与 bilibili 测试方法相同，将名称换为 WebUI 配置的国际服订阅名称，例如：

```text
/nikke 检查 NIKKE国际服
/nikke 最新 NIKKE国际服
```

「检查」确认 RSS、条数、时间和原链接；「最新」实际发送当前语言的文字和图片，必须在该订阅目标群执行，普通成员也可使用，国际服直接推送而不做 AI/Jev 筛选。

后台将 `/nikke` 显示为可折叠的原生指令组，各子指令收纳在组内。权限通过 AstrBot 原生权限装饰器注册，后台与实际执行一致：

| 子指令 | 权限 |
| --- | --- |
| `/nikke 帮助` | 所有人 |
| `/nikke 最新 订阅名称` | 所有人，仅对应订阅目标群 |
| `/nikke 活动` | 所有人 |
| `/nikke 角色 角色名` | 所有人 |
| `/nikke 技能 角色名 [等级1–10] [珍藏品1–3]` | 所有人 |
| `/nikke 状态` | 管理员 |
| `/nikke 检查 订阅名称` | 管理员 |
| `/nikke 订阅 [订阅名称]` | 管理员 |
| `/nikke 退订 [订阅名称]` | 管理员 |

`/nikke` 保持为原生指令组，裸入口显示当前可用命令示例，不保留额外平铺根入口或二次分发。子指令被后台停用后，不会从根入口绕过执行。


首次启用自动推送后，第一次成功读取仅建立基线；后续新动态才会自动发送。建议先检查来源，再确认一条图文预览，最后打开自动推送。

## 基地等级与红球查询

`/nikke 基地等级 533` 只显示该等级满学院的信用点、战斗数据、芯尘每小时数量。
`/nikke 红球 h48-32` 默认普通全通、困难已通关 48-32，显示对应基地等级和红球每小时数量。
`/nikke 红球 33-23 h18-32` 指定普通和困难已通关进度，也可写 `/nikke 红球 h18-32 33-23`。
困难进度必须带 `h`（也接受 `H`），普通进度不带前缀，两者不能重复；困难进度不得超过普通进度。
只填不带 h 的关卡、模糊指令名、缺失/多余参数时提示正确形式，不自动猜测或执行。

数据为随插件提供的 2026-11-03 源站快照，查询无需网络；详情见 `nikke/data/README.md`。
产出覆盖 1–800 级，普通关卡覆盖 2-12 至 50-36，困难覆盖 h0-1 至 h50-36（含已收录分叉）。
默认普通全通是指内置表中的最后一关 50-36；更新数据后随覆盖范围变化，超出范围不外推。
源站版本字段不等于游戏当前版本；结果为显示小数，保留 ±0.01 精度限制。
这两项查询固定使用纯文字，不受角色图片开关影响，不使用 t2i。
回复只包含结果数值；数据来源和精度信息保留在文档中，不添加到聊天结果。

## 国际服角色与技能查询

`/nikke 角色 小红帽` 返回国际服角色的稀有度、属性、企业、爆裂阶段、Lv.1 基础属性、武器参数及技能名称。
`/nikke 技能 拉毗：小红帽 7` 显示技能1、技能2和爆裂技能，省略等级时显示 10 级。
等级取官方对应数值；默认显示基础技能。

珍藏品使用同一条指令，末尾加 `珍藏品1`、`珍藏品2` 或 `珍藏品3`：

```text
/nikke 技能 拉普拉斯 珍藏品1
/nikke 技能 迪塞尔 7 珍藏品2
/nikke 技能 拉普拉斯 10 珍藏品3
```

省略技能等级仍为10级。珍藏品阶段与技能等级独立；阶段1至3逐步累积替换对应技能，
按珍藏品数据中的解锁顺序处理，不按技能编号排序。每页标明阶段、珍藏品名称及本技能是否已强化，
未解锁的槽位保留基础技能。只写“珍藏品”、阶段超出1至3或把阶段放在等级前面，均提示正确用法。
普通角色查询 `/nikke 角色` 仍显示基础资料；需要强化技能时执行上述技能指令。

珍藏品来自同一 BlaBlaLink 繁中 CDN：先读取 `equip/favorite_rare_map.json` 的 SSR 索引，
再读取 `equip/zh-tw/favorite_{id}.json`，按角色 `name_code` 关联。
首次查询需解析公开珍藏品索引及详情，同步下载最多4份，详情解析总等待上限45秒；
与角色资料共用24小时缓存、ETag、失败重试退避及国际服图片代理。基础技能查询不会请求珍藏品数据。
刷新失败但有可用缓存时标注旧缓存，校验时间取参与查询资料中最早的一份。
资料未收录、关联存在歧义、阶段结构变化或无法完整确认时，返回明确错误，不降级冒充强化技能。

「基础配置 → 角色与技能图片回复」默认关闭。开启后，角色资料渲染为图片，三个技能尽量合并在一张卡片，
过长时自动分页。图片保留基础或珍藏品阶段说明及旧缓存提示，页脚显示项目作者、GitHub 地址和 Star 提示。
来源与资料校验时间保留在文字回复和函数工具结果中，图片不再显示。
关闭时沿用文字回复；查无角色、名称歧义和参数错误仍使用简短文字提示。

图片使用 AstrBot 自带的 `html_render` 接口和已配置的文转图服务，无需在插件重复配置地址，
也不需要开启 AstrBot 的全局自动文转图开关。
请先按 [AstrBot 自建文转图说明](https://docs.astrbot.app/others/self-host-t2i.html)
将文转图服务 API 地址设为本地 t2i，例如 `http://t2i:8999`（以实际容器名为准）。
插件不会修改 AstrBot 的服务地址；如果未配置自建端点，AstrBot 可能使用其默认服务。
渲染超时或失败时只返回简短提示，不自动刷屏发送长文字；可关闭图片开关查看文字。

数据直接来自 [BlaBlaLink](https://www.blablalink.com/shiftyspad/nikke-list) 的公开繁中 CDN，
仅做本地繁简转换，不调用模型，不使用中文 Wiki 或 Enikk 回退。
角色名称支持简体、繁体、全半角标点及部分名称搜索；多个匹配会列出候选，须改用完整名称。
不提供国服名称替换或自定义别名；可用 `/nikke 角色 红帽` 查找候选。
无需填写 Cookie、账号、模型或 RSSHub，也无需开启资讯自动推送。

角色列表和详情首次查询时下载，保存在插件数据目录的 `characters/` 下，24 小时后按需校验更新，
有 ETag 时使用条件请求。刷新失败且存在可用缓存时明确标注旧缓存；无缓存时提示失败，5 分钟后可重试。
回复时间为最近资料校验时间（北京时间），不是官方发布日期。
资料属于国际服，简体显示保留国际服术语，不等同于国服本地化。
CDN 路径根据官方前端规则计算，站方调整规则后可能需要更新插件。
网络不通时可复用「国际服图片代理」配置；该设置也用于公开角色 CDN 请求。

## 随机轮询

`poll_jitter_seconds` 默认为 60。每次成功获取后，对基础间隔增加一个在 -60～+60 秒内均匀取样的偏移；最终间隔限制为 60～3600 秒。设为 0 可恢复固定间隔。失败时仍按次数指数退避，再添加扰动，最长不超过 1 小时。

首次获取立即建立基线，之后的随机检查时间持久化到 SQLite，重载不会重新抽取尚未到期的时间。后台每 5 秒检查到期任务，实际请求还受网络耗时和其他订阅处理耗时影响。`/nikke 状态` 和 `[NIKKE] 下次自动检查` 日志会显示计划时间。

该间隔控制的是 AstrBot 访问 RSSHub 的频率。RSSHub 自身的缓存也会影响访问 bilibili 的频率；随机化不保证规避平台风控，不会绕过验证码或登录要求。

## BlaBlaLink 国际服官方动态

使用 `rsshub` 兼容模式时，先完成 [RSSHub 国际服路由部署与容器自检](../deploy/rsshub/README.md#国际服路由)，再在「订阅及目标群」添加「BlaBlaLink 国际服官方动态」。新模板默认关闭、群列表为空，不会自动发送。

- 语言来源：`zh-TW` 繁中官方、`en` 全球英文官方、`ja` 日本官方、`ko` 韩国官方。它们是同一官方账号按语言返回的版本。
- 繁体转简体：默认开启，仅作用于繁中来源。英日韩保留接口原文，不调用翻译模型。
- 同一语言只添加一项订阅，在其群列表配置多个群；同一 QQ 群仅允许一种国际服语言，可同时订阅 bilibili。
- 国际服直接推送，绕过本地中奖规则、Jev 和大模型；全局 AI 筛选打开时也不会调用筛选模型。
- 先发文字，再逐张发送原图。只下载图片，不下载视频文件；视频动态附对应平台原链接。
- 每次读取最近一页（请求 10 条，可能包含额外置顶条目），沿用 300±60 秒轮询。首次启用、新增群、切换语言只建基线，不批量补发历史。停机期间超出这一页的内容可能遗漏，不代表完整历史存档。
- SQLite 保留官方原文；预览、推送和本地聊天工具按当前简繁开关显示。修改开关不重建基线，也不会重复推送。

使用所填订阅名称，例如 `/nikke 检查 NIKKE国际服`；检查只报告来源状态。`/nikke 最新 NIKKE国际服` 会实际发送图文，只能在该订阅配置的群中执行，普通成员也可使用。检查与预览沿用消息拦截。WebUI 保存后自动生效；更换插件代码时需先重载插件一次。

v0.1.16 起，在「基础配置 → 国际服图片代理（可选）」填写 HTTP/Clash mixed 代理入口，例如 `http://proxy.example:7890`。留空直连，支持 `http://用户:密码@主机:端口` 认证（特殊字符使用 URL 百分号编码）。BlaBlaLink 图片和公开角色资料走代理；RSSHub、bilibili、日历仍直连，不自动读取全局代理变量。该设置在前端掩码显示，状态只报告是否已配置，网络错误不输出代理凭据。配置保存后自动生效。容器内 localhost 指 AstrBot 自己，需填写 NAS 可访问的地址；本版不支持 SOCKS5 或 HTTPS 协议的代理入口。

国际服代理图片遇到连接重置、网络超时或传输中断时，最多尝试3次，间隔1秒、2秒；包括等待在内共用单张90秒上限。只重新下载，不重复发送正文或已发送图片；认证拒绝、证书验证失败、非法域名、超限和格式错误不做短重试。最终仍失败时，自动投递保留原有持久化续传/配图回退流程；手动预览没有后台补图保证。日志会显示底层异常类型和尝试次数，不输出代理凭据。

排查指定帖子的繁中原图，可在容器执行 `python /AstrBot/data/plugins/astrbot_plugin_nikke/scripts/diagnose_image_proxy.py --config /AstrBot/data/config/astrbot_plugin_nikke_config.json --post-id 5482869474770001176`。仅当该帖仍在繁中RSS最新一页时可用，不会偷偷改查其他帖子。诊断先检查 TCP/CONNECT/TLS，再用实际插件下载及重试路径验证完整图片；不发送消息或写数据库。

## 国际服配图回退

在 WebUI 的「国际服配图回退」功能框启用。默认关闭；开启后，国际服正文先正常发送，并单独附上该动态全部原图直链。仅当原图全部下载失败、且没有任何原图成功发送时，才进入回退队列。部分原图已发送、QQ 上传失败、bilibili 动态本身或无图动态都不会改用另一套配图。

| 配置 | 默认值与含义 |
| --- | --- |
| 启用 bilibili 配图回退 | 关闭 |
| 回退配图 bilibili 官方 UID | `3546734206650905`，无需开启它的自动推送 |
| 语义匹配模型 | 留空优先复用配置的 AI 筛选模型，否则使用该目标群当前模型 |
| 等待同步及失败重试间隔 | **5 分钟**，允许 1～60 分钟 |
| 最长等待时间 | **30 分钟**，允许 1～10080 分钟 |
| 匹配最低置信度 | 0.9 |
| 候选发布时间差上限 | 0 小时表示不限制；可按需设 24、72，最大 720 小时 |

回退功能与 AI/Jev 内容筛选独立：国际服正文不经筛选；只有等待补图且存在候选时，才调用匹配模型。模型收到原动态与国服候选的文字、发布时间及 ID，不接收图片。必须匹配同一次具体公告；不同角色、不同版本、不同倒计时天数、仅同主题或候选不明确时不选图，继续等待。语义匹配不能证明两个地区使用了相同配图，因此补图说明会明确标注 bilibili 来源并附其动态链接。

首次原图下载失败后立即检查近期 bilibili 候选；未匹配时默认每 **5 分钟**重新获取。默认最长等待 **30 分钟**，从首次进入补图队列计时，包含暂停与停机时间。期间不会因为国服尚未同步就选择不相关的最新动态。到期后停止补图，保留正文、原帖与原图直链；已到期任务不会因调大配置或再次预览而自动恢复。后续等待重试先尝试恢复国际服原图；恢复可用时优先发送原图。国服候选取自当前成功抓取与本地存档中的近期有图动态，最多 20 条，并非全量历史。候选内容不变时缓存匹配判定；新增或修改候选后重新判断。来源故障、模型异常、低置信度、图片下载或上传失败均在等待期限内按分钟继续重试。

补图说明会再次附上国际服原帖、全部原图直链和 bilibili 配图来源链接，便于同时查看两边来源。

补图使用独立 SQLite 队列，重启和重载保留等待与发送进度，等待旧动态配图不会堵住新动态。自动任务随全局自动推送暂停；显式 `/nikke 最新` 创建的补图任务在全局自动推送关闭时仍可继续。关闭回退开关或关闭图片发送会暂停补图；停用订阅或移除目标群会删除对应等待任务。更换回退来源或匹配策略时，尚未开始投递的任务重新匹配；已开始国服补图的任务保守停止，避免混合两套配图。

匹配成功后只发送一次来源说明，再逐张补充 bilibili 原图，最多 9 张。国际服正文、原帖链接和原图直链保留在原消息中，不替换为国服正文；已发送部分不重复，匹配结果和补图进度跨重启保留。`/nikke 状态` 可查看回退开关、重试间隔和等待数量。配置保存后自动生效，无需重建 RSSHub；本次代码升级需先重载插件一次。

## 命令纠错

默认启用本地纠错，不增加配置或纠错模型。仅处理 AstrBot 已识别为命令、且根名称规范化后为 `nikke` 的输入；普通聊天和 `nikkex` 等其他命名空间不受影响。仍是一个原生指令组、五个子指令，后台权限保持不变。

| 输入示例 | 行为 |
| --- | --- |
| `/nikke 最新 nikke国际服` | 唯一规范化匹配后执行 `NIKKE国际服` |
| `/nikke 最新 ＮＩＫＫＥ國際服` | 全角、繁简体和大小写归一化后执行 |
| `/nikke 最新 NIKKE国际腹` | 唯一高相似候选满足条件时执行 |
| `/nikke 最新 nikke资讯` | 相似度不足，只提示完整正确命令 |
| `/nikke 最新` | 提示当前群可用的完整命令，不自动补选 |
| `/nikke 最新 NIKKE国际服 多余内容` | 提示多余参数，不忽略后继续执行 |
| `/nikke 最心 NIKKE国际服` | 提示正确子指令，不自动改变操作 |

首先匹配配置中的原始名称，再进行 NFKC、繁简体、大小写和首尾空白规范化。仍不匹配时，以编辑距离计算 `1 - 距离 / 最大名称长度`；只有输入至少三个字符、最高分不低于 0.85、领先第二候选至少 0.15 时自动执行。即便只有一个候选，也须达到分数要求。规范化重名或候选接近时只列最多三个建议。明确的国服/bilibili/B站与国际服、繁中/英文/日服/韩服冲突也会阻止自动选择。

自动纠正先回复 `已识别为：/nikke 最新 NIKKE国际服`，随后走原有执行流程。纠错本身不调用模型；真正执行时仍按原有规则查询 RSS、发送图文、筛选 bilibili 或启动已配置的配图回退。

“最新”只使用当前群已启用的订阅，私聊不列出其他群名称；精确命中其他群的名称时保持目标群限制。管理员“检查”可使用全部已启用订阅。精确命中已停用名称时不改选其他订阅；只在当前权限范围内提示停用状态。普通成员使用“状态、检查、订阅、退订”直接沿用权限提示，不提供订阅候选。

无效输入和纯提示不查询 RSS、不调用模型、不消耗手动检查冷却、不创建补图任务，并拦截默认聊天大模型。后台停用的子指令不会通过纠错重新执行。预校验在组内参数解析前执行，初始化时绑定、卸载时清理，重载不重复注册；改写后的命令仍由原生子指令处理器执行。

## AI 内容筛选

本节的全部筛选功能仅作用于 bilibili。BlaBlaLink 国际服官方动态直接推送，不调用本地中奖规则、Jev 或远端大模型。

在 WebUI 开启 `ai_filter_enabled`，并用模型选择器选择 AstrBot 已配置的远端聊天模型（`ai_filter_provider_id`）。无需在插件中填写地址或 API Key。留空时，每项订阅使用其第一个目标群当前选择的模型；各目标群共用筛选结果。调用方式依据 [AstrBot AI 接口](https://docs.astrbot.app/dev/star/guides/ai.html)。

| 分类 | 行为 |
| --- | --- |
| giveaway_result：中奖公布、领奖或收货信息通知 | 不推送 |
| giveaway：纯转发、关注、评论抽奖 | 不推送 |
| engagement：纯拉票、集赞、互动引流 | 不推送 |
| news：更新公告、角色、维护、兑换码、游戏内活动、周年预告 | 推送 |
| other：其他或不确定 | 推送 |

优先判断本次新增正文。公布中奖结果或通知领奖时，即使转发引用的旧文包含视频、角色、版本等资讯，整条仍过滤。真正的新游戏公告附带抽奖仍应保留；旧引用中有中奖通知，不会直接触发本地过滤。模型只分类，不改写发送内容；该判断可能出错，可先用 `/nikke 检查 NIKKE官方` 检查分类与理由。

开启后，明确以“恭喜……中奖/获奖”开头并要求提交收货或领奖信息的通知，由本地规则直接过滤并记录理由，无需调用模型；包含否定或引号的复杂表述仍交给模型。其余动态仅把标题（最多 1000 字符）和正文（最多 12000 字符）提交给筛选模型（可选 Jev 前置，再按需使用大模型），按 RSSHub 的“转发自”分隔符拆成本次正文和引用原文，不提交群聊天记录、QQ 会话标识、Cookie 或图片。图片中的抽奖信息不会被识别。使用独立分类提示，不使用聊天人设、历史或工具；模型输出必须是有效分类 JSON。

首次建立基线的历史条目不调用模型；待推送的新动态在下载图片前分类。判定按来源、动态、正文、提供商和规则版本缓存到 SQLite，同一条动态在多个群只需判定一次，重启后可继续复用。切换模型、正文变化或筛选规则升级会重新判定尚待处理的动态。明确中奖通知的本地规则也受 AI 筛选开关控制。已发送的历史消息不会撤回或重新推送。

默认超时 45 秒（可配置 10～120 秒）。模型调用失败或返回无效格式时保留待投递记录，按投递退避重试，不当作“应该过滤”处理；同一来源同一目标群的后续消息会等待前一条完成。可在 WebUI 关闭 AI 筛选并保存以恢复待投递任务。已经成功过滤的记录保留为去重状态，关闭筛选不会自动补发这些历史内容。

### Jev 前置筛选

在「启用 AI 内容筛选」基础上，可再开启「启用 Jev 过滤」。明确的中奖领奖通知仍先由本地规则过滤。其余动态先提交到 TypeSafe 官方 `https://api.typesafe.ai/v1/systemone`，使用 Choice 问题返回 `normal`、`lottery` 或 `uncertain`；输入仍把新增正文和引用旧文分开。依据：[官方 Choice 接口](https://docs.typesafe.ai/primitives/choice)、[置信度说明](https://docs.typesafe.ai/confidence)。

| Jev 结果 | 后续行为 |
| --- | --- |
| 正常动态，且 confidence ≥ 配置阈值 | 直接放行，跳过现有大模型 |
| 正常但置信度不足、抽奖引流或不确定 | 交给现有大模型作最终判断 |
| 超时、401/429/其他 HTTP 错误、格式异常或无效数值 | 回退现有大模型 |

Jev 即使高置信度判为抽奖，也不会独立丢弃该条动态；最终由现有大模型判断。若大模型也失败，仍保留待投递任务并重试。AI 内容筛选总开关关闭时，本地规则、Jev 和大模型都不执行。

在插件前端填写以下选项并保存，AstrBot 会自动重载插件：

| 选项 | 默认值与说明 |
| --- | --- |
| 启用 Jev 过滤 | `jev_filter_enabled=false`，需同时开启 AI 内容筛选 |
| Jev Token | `jev_token`，从 TypeSafe 获取，只填 Token 本身，不带 Bearer；开启 Jev 时必填 |
| 正常动态放行置信度阈值 | `jev_confidence_threshold=0.8`，范围 0～1，等于阈值也放行 |
| Jev 模型 ID | `jev_model=jev-latest`，可改为账户可用的固定模型 ID |
| Jev 请求超时 | `jev_timeout_seconds=10`，可设 1～60 秒 |

阈值使用官方返回的 `confidence`，不是 normal 的类别概率，也不等于分类正确率保证。Jev 只接收标题、新增正文和转发引用文字，不接收图片地址列表、图片数据或图片 assets；判定发生在图片下载前。Token 使用前端敏感字段，仅在请求 Authorization 中发送给 TypeSafe；不提交到模型 state，不写入日志、SQLite 判定缓存或安装包样例。Token 保存在 AstrBot 本地插件配置中。

有效的 Jev 判定在 SQLite `jev_results` 中缓存 24 小时，同一动态跨群、并发及重载可复用。缓存按正文、模型 ID 和规则版本区分；修改阈值会对已缓存的 confidence 重新比较，而不复用旧放行结论。改变模型或正文会重新请求。接口失败后暂缓新 Jev 请求 60 秒，这段时间继续用大模型；已有有效缓存仍可读取。

可以使用 `/nikke 检查 NIKKE官方` 查看分类与理由。`/nikke 状态` 显示 Jev 开关和阈值；日志 `[NIKKE] Jev 判定` 显示分类、置信度、阈值以及直接放行或回退大模型。HTTP 故障仅记录状态码与异常类型，不记录响应正文。手动检查不会群发或重建基线。

### 提示词模板

配置页新增独立的「提示词模板」外框，内含「大模型筛选提示词模板」和「Jev 预筛选提示词模板」两个区块，使用 AstrBot 原生代码编辑器，支持编辑及恢复默认值。编辑器配置依据 [AstrBot 官方配置说明](https://github.com/AstrBotDevs/AstrBot/blob/master/docs/zh/dev/star/guides/plugin-config.md)。原有设置保持不变，默认继续使用原先的中奖、抽奖、引流过滤规则。

- **筛选提示词**：可修改完整的大模型筛选说明，须保留 `${classification_rules}`，运行时自动插入分类条件。普通 JSON 花括号无需转义。动态标题、新增正文和转发引用仍以独立的 JSON 用户消息提交，不需要填写动态正文变量。
- **分类条件与过滤动作**：JSON 对象，每个类别配置 `description`（判断条件）和 `filter`（`true` 过滤，`false` 推送）。可增加、删除类别，标识以小写英文字母开头，仅含小写字母、数字、下划线，最多 32 字符，总计 1～20 类。建议保留不确定类别；删除或更名默认类别时，也应修改提示词中对应的引用和示例。
- **Jev 判断提示词 / 分类条件**：分别编辑 Jev instructions 和 criteria。Jev 须保留 `normal`、`lottery`、`uncertain` 三个标识；可修改说明，正常且高置信度才直接放行。仍只提交文字信息。

例如，把 `giveaway` 的 `filter` 从 `true` 改为 `false`，即可保留该类别；也可添加 `maintenance` 类别并定义维护公告的处理动作。

修改大模型提示词或分类条件后，自动暂停本地中奖快捷规则和 Jev 预筛选，所有待判定动态均提交大模型，避免默认规则绕过自定义条件；恢复默认大模型模板及条件后，恢复原有流程。仅修改 Jev 模板时保持原有级联流程。在 WebUI 保存配置后自动重载生效，配置错误会显示日志错误并停止初始化。模板及条件变化均使对应判定缓存失效；已投递或已过滤的历史记录不会因此重发，已经开始分段发送的任务仍继续原投递。

## QQ 群活动倒计时提醒

在独立的「活动倒计时提醒」配置框中启用功能，填写目标 QQ 群号并保存即可自动重载生效。此功能与 bilibili 自动推送独立，默认关闭、目标群为空。直接读取国际服妮游社 [官方活动日历](https://www.blablalink.com/activity-calendar) 的开始及结束时间，不需要 Cookie、大模型或 RSSHub，活动提醒不经过 AI/Jev 过滤。活动名称通过内置 OpenCC t2s 词库转换为简体中文，时间使用北京时间。英文活动名保持原样。已有缓存也会在查询和发送时转换；使用原始官方字段生成活动标识，升级不会重置去重记录。转换在本地完成，无需安装额外依赖或调用模型。

- 默认在到期前 **24 小时、6 小时**各提醒一次，可修改为 1～720 的整数小时列表，自动去重。
- 单独填写接收群号，使用基础配置中的 QQ 平台选择方式，支持多个群。
- 默认提醒招募、剧情/签到、突袭/协同、超频赛季及 Buff 重置、时装/PASS；竞技场默认关闭，开启后包括赛季结束和冠军竞技场应援截止，不提醒比赛阶段。剧情附属任务不另行提醒。最后一期 Buff 与整个超频赛季同时结束时，只发送赛季结束提醒。
- 默认开启夜间提前汇总：00:00～08:00 不自动发送，本应在这段时间触发的提醒在前一天 **23:00 提前汇总**。文字明确标注提前汇总，剩余时间按实际发送时刻计算。关闭该选项则全天按阈值发送。
- 同批、同群活动按截止时间汇总为文字，附实际剩余时间、北京时间截止时间、数据更新时间及官方链接；超长消息分页。群发送与现有动态共享锁和限速。

`/nikke 活动` 供所有人查询当前和未来活动，查询不会群发。即使关闭自动提醒，也可手动查询。`/nikke 状态` 显示最近日历更新时间、下次刷新、提醒队列及获取状态；命令继续拦截默认聊天模型。

日历每小时约刷新一次（±5 分钟）；本地每分钟安排提醒。发送前若数据超过 15 分钟则先尝试刷新。网络失败使用最后成功缓存并在消息中显示更新时间，超过 **6 小时**暂停自动发送；失败按 1 分钟起、最长 1 小时退避。格式异常保留原有完整日历，不能当作官方清空活动。

活动、快照和提醒状态保存在现有 `subscriptions.sqlite3` 新增的独立表中。去重按活动、截止时间、群及提醒档位记录；重启、重载继续处理。首次启用、新增群或恢复运行时，只补发当前最紧迫的一个过期档位，不发送已结束活动。夜间恢复时等到08:00，届时仍未结束才补发。官方调整截止时间时取消旧的待发提醒，按新时间安排；完整刷新后撤下的活动停止提醒。已确认成功的页不重发，失败页独立重试。停用功能、类别或移除群会取消对应待发任务，恢复配置后继续安排未确认发送的提醒。

更新代码后需重载一次插件。可在 NAS 终端运行下方只读命令，验证 **AstrBot 容器自身**能访问官方日历；不会修改配置、SQLite 或发送群消息：

```sh
docker exec astrbot python /AstrBot/data/plugins/astrbot_plugin_nikke/scripts/check_calendar.py
```

成功输出包含 `official_code: 0`、活动数及北京时间截止时间；如果网络失败，应先检查容器的 DNS 和出站连接。也可在插件重载后使用 `/nikke 活动` 检查并查看 `[NIKKE] 活动日历更新` 日志。

动态与日历的失败日志区分 DNS 解析、TLS 证书、连接中断、请求超时、响应体传输和 JSON/编码解析错误，并附异常类型；HTTP 非 200 和业务数据校验失败仍单独报告。旧版的“网络请求或解析失败”同时包含网络与解析错误，仅凭这一行无法确定原因。请在实际运行 AstrBot 的容器内执行上述日历自检，以及 `python scripts/check_international.py --source direct --skip-images`，避免把电脑上的连通结果当作容器的网络状态。两类正文接口均直连，不读取环境代理，也不使用国际服图片代理。

官方动态与日历失败时，还会通过 AstrBot 日志器以 WARNING 记录 `官方接口故障` 与 `API原始响应`，无须开启 DEBUG。使用相同 `id` 关联请求地址、耗时、失败阶段、HTTP 状态、响应类型/上游请求编号、完整异常链和原始响应正文。正文以 JSON 字符串转义并分段，按 `part` 顺序解码拼接即可恢复；非 UTF-8 正文使用 Base64。凭据字段会脱敏，不记录请求认证头或 Cookie。正常响应不重复记录正文；失败正文最多记录 4 MiB，超限或传输中断明确标为不完整；连接阶段失败则注明“未收到响应”。历史留存随 AstrBot 日志或容器日志的保留设置执行，排障时请导出对应 `id` 的全部分段，避免仅保留最后一条摘要。

日历接口接入方式参考 [NIKKEAutoScript 日历实现](https://github.com/megumiss/NIKKEAutoScript/blob/dbe59a42e0025e4a4d7c49aba8864d03a684ffa5/module/webui/api/routes_calendar.py)，提醒调度、队列及重试由本插件实现。第一版不包含国服、维护公告解析、每日固定汇总和活动图片。

## 角色技能查询工具

在「聊天查询工具」中开启「允许模型查询角色技能」
（`character_skills_tool_enabled`，默认关闭），并在 AstrBot 中允许该工具。
需要支持工具调用的聊天模型和 Agent 执行器。

工具为 `nikke_query_character_skills(character_name, skill_level=10, treasure_phase=0)`：
角色名使用国际服完整中文名，支持简繁体；等级为1至10的整数。
每次返回一个角色的技能1、技能2及爆裂技能，三个技能使用相同等级。
`treasure_phase` 为0至3的整数：0（默认）为基础技能，1至3为对应珍藏品阶段；
与技能等级分开指定。未说明珍藏品阶段时，模型应先确认阶段，不假定满阶段。
遇到名称歧义会返回候选名称，不猜测角色。

例如自然提问“拉毗：小红帽7级技能的倍率是多少？”，模型可调用
`nikke_query_character_skills(character_name="拉毗：小红帽", skill_level=7)`。
省略等级时使用10级，也可显式传入10。
查询珍藏品例如 `nikke_query_character_skills(character_name="拉普拉斯", skill_level=7, treasure_phase=3)`。

此开关与本地动态查询独立，群聊和私聊均可使用，无需配置资讯订阅、账号或 Cookie。
工具调用时才查询 BlaBlaLink 繁中 CDN，繁简转换、24小时缓存、旧缓存提示和国际服图片代理
与 `/nikke 技能` 共用；未调用时不获取资料。返回文字资料给模型，保留校验时间、
来源、珍藏品阶段和各技能的强化状态，不直接发送群消息，也不使用 t2i。关闭开关后从当前请求中移除工具，
执行入口也会再次检查开关；不修改共享工具列表、人设或聊天历史。

## 本地官方动态查询工具

v0.1.5 新增独立存档表 `archive_entries`，与原来的投递队列共用 `subscriptions.sqlite3`。自动轮询、手动检查和预览成功时，保存每条动态的标题、正文、原链接、发布时间和图片地址；不保存图片二进制。每个来源的同一动态只存一份，正文变更会更新。首次基线、已发送及被筛选的动态均可留作资料；后续投递清空队列正文不会清空存档。移除订阅仍保留已存档资料，但聊天只读取当前启用并绑定当前群的订阅。

这并不等于拥有官方完整历史。RSSHub 路由只返回近期条目；升级时会从旧投递表恢复仍有正文的条目，已清空的正文只能在后续 RSS 仍包含该动态时补回。存档不自动清理，按天数查询时仅选指定范围，不回抓历史分页。bilibili 更换 RSSHub 基地址会生成新来源，聊天资料范围也随之切换；国际服按官方账号和语言保持来源标识。

在 WebUI 配置以下选项，保存后自动重载生效：

| 选项 | 说明 |
| --- | --- |
| 允许模型查询本地官方动态 | `chat_context_enabled`，默认关闭；保留 NAS 原有开启状态 |
| 单次工具查询天数上限 | `chat_context_days`，默认 7，范围 1～365 天；限制单次跨度，可查询存档内任意日期 |
| 单次工具返回字符上限 | `chat_context_max_chars`，默认 12000，范围 1000～50000 字符 |

v0.1.6 改为工具 `nikke_query_official_posts(start_date, end_date)`。由模型根据聊天内容决定是否调用及查询哪些日期。日期支持 `YYYY-MM-DD`、`今天` / `today`、`昨天` / `yesterday`、`N天前`，按北京时间计算并包含首尾日期。例如只查昨天，两项都填“昨天”；查最近三天，开始填“2天前”，结束填“今天”。可多次查询不同日期。未来日期、日期倒序、格式不正确或单次跨度超限时返回参数提示。

普通聊天不会自动读取 SQLite 或附加动态正文。工具仅对当前订阅的目标 QQ 群开放，私聊、未配置的群及开关关闭时从本次请求的工具列表移除；工具实际执行时也再次检查权限。只操作当前请求的工具列表副本，保留其他工具及共享工具列表。模型未选择调用时不会返回任何动态资料。

需要聊天提供商和 Agent 执行器支持工具调用，并在 AstrBot 中允许本插件的工具。没有可用工具的聊天请求不会被强制开启工具。使用官方 `@filter.llm_tool` 注册，参数通过 `Args` 文档声明；实现依据：[AstrBot 工具注册说明](https://docs.astrbot.app/dev/star/guides/ai.html)。未替换聊天人设、原问题和聊天历史。工具结果作为工具调用返回值供模型回答，而不是在每次请求前注入上下文。

工具只读取当前群绑定的启用中订阅。无发布时间则按首次收集时间查询。所有匹配订阅合计，最新优先最多 50 条，每条正文最多 3000 字符，并受总返回字符上限约束，截断时仍保留时间和原链接。资料仅覆盖已抓取记录，空结果不代表官方当天没有发布；模型应说明资料不足。外部正文会明确标记为参考数据，不应执行其中的指令。

查询不会访问 RSS、下载图片、发送群消息或额外调用分类模型。获取新资料仍依赖自动轮询或手动检查；关闭自动推送后可查询已有存档。结果可能包含被推送筛选的原始动态，推送筛选与查询工具开关相互独立。

`/nikke 状态` 显示工具开关、单次查询限制及各来源存档数量、最早和最新时间。日志 `[NIKKE] 本地动态工具查询` 显示所选日期范围、候选条数和返回字符数。读取失败会返回明确说明供模型继续答复。

## 命令拦截与日志

`/nikke` 命令进入处理函数后会立即停止事件传播，并关闭本次默认 LLM 调用。成功、失败、帮助和权限不足等分支都不会继续进入默认大模型问答。状态、检查、订阅、退订通过框架权限装饰器及命令内检查限定管理员；帮助、活动和最新允许所有人使用，最新仍校验目标群并保留原有检查间隔。原生指令组的帮助与参数错误由框架处理。

在 AstrBot 日志页面选择 INFO 或更详细级别，搜索 `[NIKKE]`。插件使用 AstrBot 自带的日志接口，记录：

- 收到的操作、订阅和目标会话；
- RSS 获取条数、最新发布时间和原链接；
- 分段文字发送成功、每张原图的序号及字节数；
- 准备发送的正文、命令回复正文，以及平台调用成功或失败；
- 自动轮询、基线和待投递数量、失败重试情况。

正文中的换行以 `\n` 显示，便于在一条日志中查看完整结果。日志不包含图片 Base64，异常详情限长并隐藏常见凭据字段。“发送成功”表示平台调用正常返回，仍需在 QQ 群确认最终展示。

插件代码更新后，在插件页重载「NIKKE 资讯助手」，通过加载日志确认版本，再执行状态和预览指令。国际服路由代码更新后还需重启 RSSHub。

## 投递与存储

- RSSHub 负责平台 Cookie 和内容获取；插件不需要 bilibili Cookie。
- 原创和转发均保留；视频发送封面和链接，不下载视频、不翻译。
- 每条动态先发送一条纯文字消息，再逐张发送最多 9 张原图，每张图片单独一条消息。单张下载上限为 64 MiB，下载超时 90 秒，平台发送超时 120 秒。识别 bilibili CDN 的 `@` 缩略变换后缀并请求原始地址；插件不缩放、不重新编码图片。QQ 或 OneBot 端是否再次处理图片仍取决于平台。
- 下载和发送按单张串行进行，不再同时缓存多张原图，也不再使用旧版 16 MiB 总图片预算。文本超过 3500 字符时截断并保留原链接。
- 自动投递用 SQLite 的 `sent_parts` 记录已确认成功的文字及各张图片。某张下载或上传失败时仍尝试其他图片，失败部分留在队列按退避重试；重载后继续未完成部分，不重复发送已确认成功的文字及其他图片。已开始发送的动态在重试时不重新筛选。手动“最新”是一次独立预览，不创建新的自动投递任务。
- 去重和队列保存在 `data/plugin_data/astrbot_plugin_nikke/subscriptions.sqlite3`，按来源、动态 ID 和目标群分别记录。重启继续待投递任务，各群独立重试。
- 来源失败逐步延长重试至 1 小时，不推进基线；发送失败从 1 分钟逐步延长至 1 小时。
- 关闭全局自动推送保留队列；移除目标群、删除或停用订阅会清除相应队列，重新添加时重新建立基线。bilibili 更换 RSSHub 基地址也视为新来源；国际服来源标识由官方账号和语言决定，修改地址或简繁开关不会重建基线。
- RSS 只包含近期条目，长时间停机可能漏掉来源已移除的动态。发送成功后若进程在记录结果前中断，重启可能重复发送。

## 国际服非中文动态翻译

在「国际服非中文动态翻译」中开启开关，选择翻译模型。只对英文、日文、韩文国际服来源生效，群内发送简体译文，配图优先使用同帖繁中原图，缺失时使用所选语言原图；繁中正文仅作为模型的术语参考，不额外发送繁中全文。bilibili、繁中来源及聊天资料查询保留原有行为，SQLite 动态存档始终保留原文。

- 参考按同一 `post_uuid` 精确匹配，优先读取原始存档，没有才读取 RSSHub 繁中路由；不以最新动态或相近主题代替。
- 缺少同帖参考时每分钟重新检查，默认最多等待 **10 分钟**，可配置 0～1440 分钟；重载、重启和多群共用已保存的起始时间。0 表示不等待。
- 参考请求失败或等待到期后直接翻译外语原文；未确认的专名要求保留原文，不追加翻译过程说明；繁中动态或配图缺失时照常发送所选语言原图，不因缺少术语参考而丢弃图片。模型调用失败、译文为空、结果无法解析或链接被改动时保留自动投递任务重试，不抢先发送外语正文或图片。未发送内容的翻译结果校验失败任务，在退避等待期间允许后续动态继续；到达重试时间后再优先尝试旧任务，已发送部分内容的任务仍按原顺序续传。
- 提示词要求角色、活动等专名参考繁中官方写法转简体。专名检查兼容全半角、空格及冒号排版差异；术语映射缺失、格式异常或未逐字匹配参考仅作日志提示，**不阻断推送，不因此重新调用模型**。有效译文可接受 JSON 代码围栏与额外辅助字段，只发送标题、正文。正文中的日期、数量、时区以所选语言原文为准。
- 翻译成功后缓存译文，多群及失败续传复用；先发译文，再逐张发送配图：优先同帖繁中原图，繁中不存在或无图时使用所选语言原图。正常推送不附加 AI 译文说明或繁中配图来源链接，保留所选语言原帖链接。所选图片地址与投递进度一并持久化，失败重试、重载或之后关闭翻译开关均沿用既定配图。繁中原图全部下载失败时仍可按已有开关进入 bilibili 配图回退，原始国际服图片直链保留。翻译不调用 Jev 或内容筛选，不向模型提交图片。
- `/nikke 最新` 使用相同翻译流程，但手动预览缺少参考时会立即提示稍后重试，不在命令中阻塞等待十分钟，也不创建额外推送任务。`/nikke 检查` 只检查 RSS，不调用翻译模型。`/nikke 状态` 显示翻译开关及等待上限。

翻译复用 AstrBot 已配置的模型和认证，不修改共享聊天配置。**OpenAI 兼容聊天适配器**通过其 SDK 发送本次翻译的思考控制参数，不继承共享聊天请求体；其他适配器通过 AstrBot 标准模型接口翻译，不支持逐次关闭思考时允许使用默认模式。因 AstrBot 4.10.4 的 OpenAI 兼容适配器不会将部分逐次调用参数传入请求，使用此类模型时通过其 SDK 客户端单独发送翻译请求。「关闭翻译模型思考」默认开启；关闭后不附加思考控制参数，允许模型使用默认模式（不强制开启思考）。开启时，内置 Qwen（`enable_thinking=false`）和 DeepSeek（`thinking.type=disabled`）两种接口，`auto` 按模型名识别。未知模型也可以正常翻译。接口明确拒绝关闭思考参数（HTTP 400/422，错误指出对应参数）时，移除参数重试一次，并在本次插件运行期间记住该模型/参数组合；认证失败、限流、服务错误和其他参数错误不会触发这种回退。模型仍返回思考时，使用最终译文；思考字段或前置 `<think>` 块不会发送到群。两次调用共用一个翻译超时上限。

「自定义关闭思考参数」支持 JSON 键值对和嵌套对象，仅在关闭思考开关开启时发送；同名顶层键覆盖内置值，选择 `custom` 时只发送自定义参数。比如模型服务商采用以下格式时可以填写：

```json
{"chat_template_kwargs":{"enable_thinking":false}}
```

参数实际合并到翻译请求体顶层，不是将 `extra_body` 字段发给服务商。无需重新填写模型地址或密钥，不能覆盖模型、消息、工具或认证字段。更换开关、模式或参数后，译文缓存使用新策略；已发出的消息及图片续传不重复翻译。依据：[AstrBot 适配器源码](https://github.com/AstrBotDevs/AstrBot/blob/v4.10.4/astrbot/core/provider/sources/openai_source.py)、[Qwen 接口说明](https://www.alibabacloud.com/help/en/model-studio/deep-thinking)、[DeepSeek 接口说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

功能默认关闭，升级不会修改现有群号、Cookie、Token、数据库或订阅语言。更新插件代码后重载一次；之后在 WebUI 保存配置会自动生效，无需重建 RSSHub。
